# Project Knowledge Policy

- Project knowledge lives in `.ai/`.
- For non-trivial work, read `.ai/INDEX.md`, select only the relevant chunks, then consult only relevant entries from the global knowledge index.
- Project requirements, decisions, and conventions override global defaults.
- Report drift between documentation and implementation rather than assuming the code wins.
- `.ai/KNOWLEDGE-PROPOSAL.md` is candidate-only and non-authoritative. Do not add proposals merely because code changed.
- Knowledge curation is user-controlled and must occur in the current session.
- Preserve `CLAUDE.md` as existing repository guidance, but route current sync semantics through the chunks selected by `.ai/INDEX.md`.
